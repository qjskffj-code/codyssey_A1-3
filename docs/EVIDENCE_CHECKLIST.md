# A1-3 제출 증빙 체크리스트

## 제출 전 필수 확인

- [ ] 별도 GitHub 공개 저장소 URL
- [ ] Vercel 배포 URL
- [ ] Vercel에 `OPENAI_API_KEY` 환경변수 등록
- [ ] 배포 URL에서 `/api/frame` 실제 호출 성공
- [ ] 저장소에 `.env`, 실제 데이터, 비공개 참고자료가 없는지 확인
- [ ] README의 Live demo 항목에 최종 URL 반영

## 화면 캡처

캡처 이미지는 `screenshots/submission/`에 보관할 수 있다. 개인 데이터가 찍힌 이미지는 `screenshots/private/`에만 두며 Git에 올리지 않는다.

- [ ] **데스크톱 메인 화면**: Today 전체와 사이드바가 보이도록 캡처
- [ ] **3개 이상 화면/섹션**: Today, Projects, AI Frame, About의 이동이 확인되도록 캡처
- [ ] **모바일 반응형**: 390px 전후 너비에서 Today 또는 AI Frame 캡처
- [ ] **AI 입력 화면**: 프로젝트 이름·원하는 변화·허들을 입력한 상태
- [ ] **AI 출력 화면**: Metric Goals부터 First Actions까지 결과가 보이는 상태
- [ ] **AI 실패 화면**: 필수 입력 누락 또는 API 오류 안내가 보이는 상태
- [ ] **로컬 저장 UX**: 항목 추가 또는 완료 후 `Saved locally` 표시

## 기능 검증 시나리오

### Today

- [ ] `＋ Add`로 항목 추가
- [ ] 완료 버튼을 눌러 완료율과 남은 개수 변경 확인
- [ ] 항목 삭제
- [ ] 새로고침 후 데이터 유지
- [ ] Reset demo data로 가상 데이터 복원

### Projects

- [ ] 세 프로젝트 카드를 각각 선택
- [ ] 선택 상태와 상세 내용이 함께 변경
- [ ] Metric Goal, Desired Response, Hurdle, Boundaries 표시 확인

### AI Frame

- [ ] 정상 입력으로 결과 생성
- [ ] 결과가 정해진 여섯 영역으로 구조화되어 표시
- [ ] 빈 필수 입력 시 전송되지 않고 안내 표시
- [ ] 요청 중 버튼 중복 클릭 방지
- [ ] 오류 후 입력 내용 유지

### 반응형·브라우저

- [ ] 데스크톱 Chrome 또는 Edge
- [ ] 모바일 너비에서 사이드 메뉴 열기/닫기
- [ ] 320px 너비에서 가로 스크롤이나 텍스트 겹침 없음

## AI 코딩 활용 증빙

- [ ] AI와 논의한 문제 정의 또는 구조 설계 화면
- [ ] 구현 과정의 요청과 수정 결과 화면
- [ ] 단순 생성이 아니라 검증·수정한 사례 한 가지
- [ ] 아래 설명을 자신의 말로 정리

> AI를 코드 생성 도구로만 사용하지 않고, 참고 앱의 구조를 해석하고 상호작용의 이유를 검토하며 구현 결과를 반복해서 비교·수정하는 협업 도구로 사용했다.

## 최종 제출 문구에 포함할 내용

- [ ] Away에서 시작했지만 실제 사용 가능성에 의문을 느낀 전환점
- [ ] 완성도 높은 제품을 분석하며 UI/UX가 사용 의지에 미치는 영향을 배운 과정
- [ ] Bound가 단순 복제가 아니라 Metric Goal, Desired Response, Hurdle, Boundary로 확장한 점
- [ ] 비상업적 학습 프로젝트 및 비제휴 사실
- [ ] 가상 데이터 기반 데모라는 점
- [ ] 앞으로 실생활 사용과 관찰을 통해 개선할 계획
